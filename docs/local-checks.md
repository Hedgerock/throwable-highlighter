# Локальная проверка подготовленного коммита

## Назначение

Перед созданием коммита выполняются автоматические проверки IntelliJ-плагина и технического прототипа VS Code.

Проверяется состояние индекса Git. Изменения рабочей копии, которые не добавлены в индекс, не участвуют в проверке.

Проверки реализованы согласно [ADR-0016](decisions/0016-local-pre-commit-checks.md).

---

## Окружение

Для выполнения проверок требуется:

- Git;
- Node.js 22 и npm;
- JDK 25.

Инструменты должны быть доступны процессу Git при запуске из терминала и IDE.

В Windows используется Git for Windows. Команды Gradle Wrapper и npm запускаются через `cmd.exe`.

Загрузка зависимостей и компонентов проверки требует доступа к соответствующим репозиториям.

---

## Подключение

Команды выполняются из корня репозитория:

```powershell
git config --local core.hooksPath .githooks
git config --local --get core.hooksPath
```

Ожидаемое значение:

```text
.githooks
```

Подключение выполняется отдельно для каждого локального клона. Настройка `core.hooksPath` не передается через коммиты.

Файл `.githooks/pre-commit` хранится с окончаниями строк LF, без BOM и с режимом `100755`.

---

## Состав проверок

Hook запускает `scripts/check-staged.cjs`.

Скрипт последовательно выполняет:

1. Тесты механизма локальной проверки.
2. `test verifyPlugin buildPlugin --no-daemon` через Gradle Wrapper.
3. `npm ci` в каталоге `prototypes/vscode`.
4. `npm run check` в каталоге `prototypes/vscode`.

Все этапы выполняются независимо от состава изменённых файлов. Изменения только в документации проходят тот же набор проверок.

Ошибка этапа прерывает выполнение последующих команд.

---

## Проверяемое состояние

Содержимое индекса Git выгружается во временный каталог. Зависимости npm и результаты сборки размещаются во временной копии.

Рабочие файлы и индекс исходного репозитория не изменяются. Автоматическое исправление форматирования и добавление файлов
в индекс не выполняются.

Временный каталог удаляется после завершения проверок или обработки ошибки.

Изменения, внесённые после `git add`, попадают в проверку только после повторного добавления соответствующих файлов в индекс.

---

## Ручной запуск

Полная проверка индекса без создания коммита:

```powershell
node scripts/check-staged.cjs
```

Запуск подключённого hook без создания коммита:

```powershell
git hook run pre-commit
```

При успешном завершении выводится сообщение:

```text
[local-ci] Staged checks passed.
```

Отдельный запуск тестов механизма проверки:

```powershell
node --test scripts/test/check-staged.test.cjs
```

Тесты используют временные Git-репозитории и проверяют соответствие снимку индекса, сохранение рабочей копии, обработку
ошибок и очистку временных каталогов. Запуск Gradle и npm в этих тестах подменяется.

---

## Ошибка проверки

Ошибка подготовки снимка, недоступность инструмента или ошибка команды завершает hook с ненулевым кодом. Создание коммита
прерывается.

После исправления файлов соответствующие изменения повторно добавляются в индекс.

Локальный hook может быть отключён или обойдён средствами Git. Проверки GitHub Actions сохраняются.
