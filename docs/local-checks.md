# Локальная проверка подготовленного коммита

## Назначение

Перед созданием коммита выполняются автоматические проверки, выбранные по составу изменений индекса Git.

Тесты механизма локальной проверки выполняются всегда. Проверки IntelliJ-плагина и технического прототипа VS Code выбираются
независимо.

Проверяется состояние индекса. Изменения рабочей копии, которые не добавлены в индекс, не участвуют в проверке.

Подготовка снимка определена [ADR-0016](decisions/0016-local-pre-commit-checks.md).
Правила выбора проверок определены [ADR-0018](decisions/0018-selective-local-checks.md).

---

## Окружение

Требования к окружению зависят от выбранных проверок.

| Проверки                    | Необходимые инструменты |
|-----------------------------|-------------------------|
| Механизм локальной проверки | Git и Node.js 22        |
| IntelliJ-плагин             | JDK 25                  |
| Прототип VS Code            | npm                     |

Инструменты должны быть доступны процессу Git при запуске из терминала и IDE.

В Windows используется Git for Windows. Команды Gradle Wrapper и npm запускаются через `cmd.exe`.

Загрузка зависимостей и компонентов проверки требует доступа к соответствующим репозиториям.

---

## Подключение

Команды выполняются из корня репозитория:

```powershell
git config --local core.hooksPath .githooks
git config --local --get core.hooksPath
```

Ожидаемое значение:

```text
.githooks
```

Подключение выполняется отдельно для каждого локального клона. Настройка `core.hooksPath` не передается через коммиты.

Файл `.githooks/pre-commit` хранится с окончаниями строк LF, без BOM и с режимом `100755`.

---

## Состав проверок

Hook запускает `scripts/check-staged.cjs`.

Список изменений определяется относительно `HEAD`. До первого коммита учитываются все файлы, добавленные в индекс.

План проверок строится по следующим правилам:

| Пути                                                                                   | Проверки платформ |
|----------------------------------------------------------------------------------------|-------------------|
| `README.md`, `CHANGELOG.md`, `prototypes/vscode/README.md`                             | Не выполняются    |
| Markdown-файлы в `docs`, кроме `docs/specification/fixtures`                           | Не выполняются    |
| `src/**`, `gradle/**`                                                                  | IntelliJ-плагин   |
| `build.gradle.kts`, `settings.gradle.kts`, `gradle.properties`                         | IntelliJ-плагин   |
| `gradlew`, `gradlew.bat`                                                               | IntelliJ-плагин   |
| Остальные файлы в `prototypes/vscode/**`                                               | Прототип VS Code  |
| `docs/specification/fixtures/**`, `.githooks/**`, `scripts/**`, `.github/workflows/**` | Обе платформы     |
| Путь без отдельного правила                                                            | Обе платформы     |

Для смешанного набора изменений группы проверок объединяются.

Удаление файла учитывается по его пути. При переименовании учитываются исходный и новый пути.

Сначала выполняются все тесты механизма локальной проверки.

Для IntelliJ-плагина запускаются задачи `test verifyPlugin buildPlugin --no-daemon` через Gradle Wrapper.

Для прототипа VS Code последовательно выполняются:

1. Установка зависимостей через `npm ci`.
2. Проверка форматирования по подготовленной выборке.
3. Компиляция через `npm run compile`.
4. Автоматические тесты на Node.js через `npm test`.

Для выбранной платформы перечисленные проверки выполняются полностью.

Браузерные проверки панели запускаются отдельно командой `npm run test:browser` из каталога прототипа.
Они не входят в pre-commit согласно [ADR-0019](decisions/0019-browser-color-settings-tests.md).

Ошибка этапа прерывает выполнение последующих команд.

## Проверяемое состояние

Перед определением изменений создаётся временная копия индекса Git.

План проверок и выгрузка файлов используют эту копию. Если Git передал индекс через `GIT_INDEX_FILE`, копируется
указанный индекс.

Последующие изменения исходного индекса не изменяют подготовленный снимок.

Содержимое копии индекса выгружается во временный каталог. Зависимости npm и результаты сборки размещаются в снимке.

Выборка форматирования сохраняется отдельно от файлов снимка и передаётся форматтеру через `--selection`.
Форматтер не определяет изменения Git повторно.

Рабочие файлы и индекс исходного репозитория не изменяются. Автоматическое исправление форматирования и добавление файлов
в индекс не выполняются.

Временный каталог удаляется после завершения проверок или обработки ошибки.

Изменения, внесённые после `git add`, попадают в проверку только после повторного добавления соответствующих файлов в индекс.

## Форматирование в pre-commit

Для обычных изменений прототипа проверяются изменённые отслеживаемые файлы из снимка индекса.

Изменение конфигурации форматирования или npm-зависимостей прототипа включает проверку всех его отслеживаемых файлов.
К таким файлам относятся:

- `.prettierrc` и `.prettierrc.*`;
- `prettier.config.*`;
- `.prettierignore`;
- `.editorconfig`;
- `package.json`;
- `package-lock.json`.

Изменения общей инфраструктуры и путей без отдельного правила также включают полную проверку форматирования
отслеживаемых файлов прототипа.

В Prettier передаются существующие обычные файлы с поддерживаемым форматом. Учитываются `.gitignore` и
`.prettierignore` прототипа.

Удалённые, неотслеживаемые и игнорируемые файлы, каталоги и символические ссылки исключаются.

При отсутствии подходящих файлов проверка форматирования завершается успешно.

## Ручной запуск

Команды выполняются из корня репозитория.

Проверка индекса с выбором групп по изменениям:

```powershell
node scripts/check-staged.cjs
```

Полная проверка обеих платформ и всех отслеживаемых файлов прототипа, подходящих для форматирования:

```powershell
node scripts/check-staged.cjs --all
```

Полный режим сохраняет проверку снимка индекса. Незастейдженные и неотслеживаемые файлы рабочей копии в него не включаются.

Запуск подключённого hook без создания коммита:

```powershell
git hook run pre-commit
```

При успешном завершении выводится сообщение:

```text
[local-ci] Staged checks passed.
```

Отдельный запуск всех тестов механизма проверки:

```powershell
node --test "scripts/test/*.test.cjs"
```

Тесты покрывают классификацию путей, чтение изменений Git, выбор файлов форматирования, выполнение команд и обработку ошибок.

Интеграционные сценарии используют временные Git-репозитории. Проверяются различия рабочей копии и индекса, переданный
индекс, неизменность подготовленного снимка, запуск из настоящего pre-commit hook и очистка временных каталогов.

Запуск Gradle и npm в тестах подменяется.

---

## Ошибка проверки

Ошибка определения изменений, подготовки снимка, недоступность инструмента или ошибка выбранной команды завершает hook
с ненулевым кодом. Создание коммита прерывается.

После исправления файлов соответствующие изменения повторно добавляются в индекс.

Локальный hook может быть отключён или обойдён средствами Git. Проверки GitHub Actions сохраняются.
