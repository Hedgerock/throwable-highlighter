# Контракт Java-подсветки Throwable

## Назначение

Документ определяет единое поведение подсветки `Throwable` и его наследников в Java-коде.

Контракт используется при разработке адаптера IntelliJ Platform и адаптеров для будущих платформ.

Документ не определяет API, структуру модулей, формат настроек и способ публикации конкретной реализации.

---

## Область применения

Подсветка применяется только к Java-коду.

Тип должен быть разрешён средствами Java-поддержки платформы и являться `Throwable` либо его прямым или транзитивным наследником.

Неразрешённые типы и типы, не являющиеся `Throwable` или его наследниками, не подсвечиваются.

---

## Контексты подсветки

| Контекст | Применение                                    | Граница подсветки                |
|----------|-----------------------------------------------|----------------------------------|
| `CLASS`  | Объявление класса и обычные ссылки на тип     | Имя класса или ссылка на тип     |
| `IMPORT` | Явный импорт типа                             | Только имя импортируемого класса |
| `CATCH`  | Тип в параметре `catch`                       | Только ссылка на тип             |
| `THROWS` | Тип в списке `throws` метода или конструктора | Только ссылка на тип             |

Контекст `CLASS` применяется к объявлениям и обычным ссылкам на тип, включая использование в полях, локальных переменных,
параметрах, выражениях создания объекта и наследовании.

Контекст `IMPORT` применяется только к явному импорту типа.

Контекст `CATCH` применяется только к ссылке на тип в параметре `catch`.

Контекст `THROWS` применяется только к ссылке на тип в списке `throws` метода или конструктора.

---

## Правило определения типа

Подсветка определяется по разрешённому Java-типу, а не по имени класса.

Стандартные типы исключений, пользовательские исключения и исключения с транзитивным наследованием используют одинаковое
правило определения.

```java
class ApplicationException extends RuntimeException {
}
```

`ApplicationException` относится к `Throwable` и подсвечивается во всех поддерживаемых контекстах.

---

## Правила цветов

Каждый контекст поддерживает отдельную настройку визуального стиля.

По умолчанию контексты `IMPORT`, `CATCH` и `THROWS` используют тот же визуальный стиль, что и `CLASS`.

Платформа может реализовать это поведение наследованием настройки или эквивалентным механизмом.

Отдельная настройка `IMPORT` влияет только на явные импорты.

Отдельная настройка `CATCH` влияет только на типы в параметрах `catch`.

Отдельная настройка `THROWS` влияет только на типы в списках `throws`.

---

## Правила применения контекстов

В явном импорте подсвечивается только имя импортируемого класса.

```java
import java.io.IOException;
               ^^^^^^^^^^^
```

Имя пакета в импорте не подсвечивается.

Wildcard import не подсвечивается.

```java
import java.io.*;
```

В `catch` подсвечивается только ссылка на тип.

```java
catch (IOException exception) {
       ^^^^^^^^^^^
}
```

Ключевое слово `catch`, имя параметра и ссылки внутри тела блока `catch` не относятся к контексту `CATCH`.

В multi-catch каждый тип определяется и подсвечивается отдельно.

```java
catch (IOException | IllegalArgumentException exception) {
       ^^^^^^^^^^^   ^^^^^^^^^^^^^^^^^^^^^^^^
}
```

Ссылка на тип внутри тела `catch` использует контекст `CLASS`.

```java
catch (IOException exception) {
       ^^^^^^^^^^^
    IOException copy = exception;
    ^^^^^^^^^^^
}
```

В `throws` подсвечивается только ссылка на тип.

```java
void execute() throws IOException {
                      ^^^^^^^^^^^
}
```

Контекст применяется к спискам `throws` методов и конструкторов.

Ключевое слово `throws`, разделители и ссылки на типы внутри тела метода или конструктора не относятся к контексту `THROWS`.

В списке `throws` каждый тип определяется и подсвечивается отдельно.

```java
import java.io.IOException;

void execute() throws IOException, IllegalArgumentException {
                      ^^^^^^^^^^^  ^^^^^^^^^^^^^^^^^^^^^^^^
}
```

Ссылка на тип внутри тела метода использует контекст `CLASS`.

```java
import java.io.IOException;

void execute() throws IOException {
                      ^^^^^^^^^^^
    IOException copy = null;
    ^^^^^^^^^^^
}
```

## Границы базовой спецификации

Подсветка слова `throw` не входит в контракт.

Подсветка ссылок в Javadoc `@throws` и `@exception` не входит в обязательные сценарии общей базовой спецификации.

### Расширение IntelliJ Platform

Плагин IntelliJ Platform поддерживает отдельный контекст `JAVADOC`
согласно [ADR-0020](../decisions/0020-intellij-javadoc-throwable-highlighting.md).

Расширение применяется к именам классов Throwable в блочных тегах `@throws` и `@exception` методов и конструкторов.

Реализация этого контекста на других платформах рассматривается отдельно. Она не является условием первого публичного
выпуска VS Code.

---

## Сохранение стандартной Java-подсветки

Подсветка Throwable не изменяет визуальный стиль Java-элементов, которые не относятся к целевому типу.

Модификаторы доступа, ключевые слова, комментарии, имена переменных, параметры и другие стандартные элементы Java сохраняют
стиль активной темы или цветовой схемы платформы.

---

## Обязательные сценарии

Каждая реализация контракта проверяется на следующих сценариях:

- объявление пользовательского наследника `Throwable`;
- обычная ссылка на стандартное исключение;
- обычная ссылка на пользовательское исключение;
- транзитивное наследование `Throwable`;
- явный импорт типа;
- отсутствие подсветки имени пакета в импорте;
- отсутствие подсветки wildcard import;
- одиночный `catch`;
- multi-catch;
- отсутствие подсветки не-`Throwable` типа в `catch`;
- использование контекста `CLASS` для ссылки в теле `catch`;
- тип `Throwable` в `throws` метода;
- тип `Throwable` в `throws` конструктора;
- несколько типов `Throwable` в одном списке `throws`;
- отсутствие подсветки не-`Throwable` типа в списке `throws`;
- использование контекста `CLASS` для ссылки внутри тела метода или конструктора;
- отсутствие подсветки неразрешённого типа;
- сохранение стандартной Java-подсветки нецелевых элементов.
