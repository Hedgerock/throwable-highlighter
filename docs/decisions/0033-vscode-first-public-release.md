# ADR-0033: Определить границы первого публичного выпуска VS Code

## Статус

Принято.

---

## Контекст

[ADR-0004](0004-platform-expansion.md) определяет VS Code как первую платформу для технического исследования.
Прототип реализует подсветку в контекстах `CLASS`, `IMPORT`, `CATCH` и `THROWS`, настройку цветов и локальную диагностику.

Интеграционные проверки запускают расширение из каталога разработки с `redhat.java` в режиме `Standard`.
Перед публичным выпуском требуется определить поддерживаемое окружение и проверить устанавливаемый пакет.

---

## Решение

### Идентификаторы и выпуск

Публичная поддержка VS Code начинается с первого выпуска, прошедшего проверки этого решения. Расширение для VS Code версионируется,
собирается и публикуется отдельно.

Расширение использует идентификатор `hedgerock.throwable-highlighter`. Настройки и пользовательские команды используют
пространство имён `throwableHighlighter`. `Open Color Settings` и `Open Diagnostics` входят в пользовательский интерфейс.
`Inspect Definition` доступна в режиме разработки.

### Перенос настроек прототипа

При переходе на первый публичный выпуск пользователь переносит явно заданные настройки
с префикса `throwableHighlighter.prototype.` на `throwableHighlighter.` отдельно
в областях `User` и `Workspace`.

Для каждого контекста цвет и источник проверяются вместе. Явные значения `null` и `""` переносятся в исходном виде. При конфликте
пользователь выбирает итоговые значения. Старые ключи удаляются из той же области после проверки переноса в панели цветов.

Изменение опубликованных ключей, формата значений или областей настройки сопровождается
отдельным решением о совместимости и миграции.

### Java-поддержка

Первый выпуск поддерживает локальные Java-проекты в настольной версии VS Code на Windows.
Поддерживаемый Java-провайдер — Language Support for Java by Red Hat (`redhat.java`) в режиме `Standard`.

Java-провайдер устанавливается пользователем. Throwable Highlighter активируется самостоятельно. При отсутствии `redhat.java`
доступны панель цветов и локальный журнал. Проверка готовности записывает `extension-unavailable`. До подтверждения типа
сохраняется стандартная Java-подсветка.

### Условия выпуска

Кандидат собирается в VSIX. Пакет содержит скомпилированный код расширения, ресурсы панели, лицензию и пользовательскую документацию.

Кандидат устанавливается в чистый профиль VS Code. Проверка охватывает следующие сценарии.

- Открытие панели и журнала в профиле без `redhat.java`
- Применение цветов и открытие журнала после установки Java-поддержки
- Подсветка в Maven и Gradle после импорта проекта без переключения редактора
- Определение наследника из другого модуля и типа из внешней зависимости
- Сохранение стандартной подсветки для класса вне иерархии `Throwable`

В матрице совместимости фиксируются ОС, версии VS Code и `redhat.java`, JDK проекта, тип рабочей области и результат проверки.
Нижняя граница `engines.vscode` подтверждается установкой кандидата и прогоном на заявленной версии VS Code.

Контрольные бюджеты производительности проверяются на кандидате согласно
[ADR-0031](0031-vscode-release-performance-budgets.md).

---

## Рассмотренные варианты

### Обязательная зависимость от `redhat.java` в манифесте

`extensionDependencies` связывает активацию Throwable Highlighter с доступностью Java-расширения. Для панели цветов и
локального журнала требуется самостоятельная активация.

---

## Последствия

Пользовательская документация описывает установку, подключение `redhat.java`, выбор цвета, открытие журнала и перенос
настроек прототипа.

Результаты проверки кандидата фиксируются в матрице совместимости и материалах выпуска.

---

## Не входит в решение

Поддержка других Java-провайдеров, дополнительных ОС и удалённых рабочих областей рассматривается после отдельных проверок.
Расширение каталога `Throwable` определяется по воспроизводимым сценариям разрешения типов.
