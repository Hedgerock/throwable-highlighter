# ADR-0040: Использовать Type Hierarchy для определения наследников Throwable в VS Code

**Область действия** — VS Code

## Статус

Принято.

---

## Контекст

`JavaTypeDefinitionResolver` подтверждает объявление Java-класса и обходит цепочку его родителей. Обход завершается положительным
результатом, если достигает подтверждённого типа из `ThrowableTypeCatalog`. Если данные о родителе недоступны,
принадлежность класса к `Throwable` остаётся неподтверждённой.

VS Code предоставляет команды `vscode.prepareTypeHierarchy` и `vscode.provideSupertypes`. Тест Extension Host подтвердил
получение цепочки `BaseException → RuntimeException → Exception → Throwable` на VS Code 1.144.0 с `redhat.java` 1.58.0.

---

## Решение

Resolver сначала проверяет исходный символ и обходит цепочку по правилам ADR-0013. Если обход прерывается из-за недоступных
данных о родителе, resolver может один раз запросить Type Hierarchy с позиции имени последнего однозначно подтверждённого класса.

Resolver сверяет начальный узел с подтверждённым объявлением и далее запрашивает непосредственные родительские классы.
Положительный результат требует подтверждения полного имени `java.lang.Throwable` по данным объявления. Короткое имя `Throwable`
и отображаемое поле `detail` сами по себе для этого недостаточны.

При пустом ответе, неоднозначном родителе, ошибке провайдера, цикле или исчерпании лимита глубины результат резервного
обхода остаётся `unavailable`. Такой результат не попадает в кэш подтверждённых результатов.

Резервный обход использует остаток общего лимита глубины. Его команды проходят через общий ограничитель обращений к Java-провайдерам.
Результат применяется только для актуального поколения resolver.

---

## Последствия

Перед подключением к обновлению подсветки проверяются:

- `AssertionError` из JDK и наследник исключения из внешней зависимости;
- одноимённый класс `Throwable` из пакета проекта и вызовы обычных методов;
- недоступность провайдера и конкуренция нескольких обходов;
- работа на минимальной поддерживаемой версии VS Code 1.101.0.

В одном из сценариев Extension Host существующий обход должен вернуть `unavailable`, а резервный обход — подтвердить
`java.lang.Throwable` для того же кандидата. Существующие сценарии подсветки и бюджеты производительности проверяются
по ADR-0013 и ADR-0031.

---

## Не входит в решение

- Ведение полного каталога типов JDK.
- Отдельное оформление checked exceptions, runtime exceptions и errors.
