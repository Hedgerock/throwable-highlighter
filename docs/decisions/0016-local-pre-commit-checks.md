# ADR-0016: Локальная проверка подготовленного коммита

## Статус

Принято.

---

## Контекст

Проект содержит IntelliJ-плагин и технический прототип VS Code.

Автоматические проверки обеих частей выполняются в GitHub Actions. Перед локальным коммитом проверки запускаются вручную.

Коммит может содержать только часть изменений рабочей копии. Проверка рабочей копии не подтверждает корректность состояния,
подготовленного к коммиту.

---

## Решение

Перед созданием коммита выполняется репозиторный `pre-commit` hook.

Hook хранится в каталоге `.githooks`. Его подключение выполняется явно для каждого клона через `core.hooksPath`.

Проверяемое состояние формируется из индекса Git во временном каталоге. Незастейдженные и неотслеживаемые файлы рабочей
копии не включаются в проверяемый снимок.

Hook не изменяет рабочие файлы и индекс, не использует автоматический stash и не добавляет файлы в коммит.

Перед каждым коммитом проверяются обе части проекта независимо от состава изменённых файлов:

- IntelliJ-плагин: `test verifyPlugin buildPlugin --no-daemon` через Gradle Wrapper;
- прототип VS Code: `npm ci` и `npm run check` из каталога `prototypes/vscode`.

Установка npm-зависимостей и результаты сборки размещаются во временной копии.

Ошибка подготовки снимка, недоступность необходимого инструмента или ошибка проверки завершают hook с ненулевым кодом. Коммит
не создаётся.

Проверки доступны для самостоятельного локального запуска. Их набор соответствует проверкам workflow CI.

Автоматическое исправление форматирования, подписание и публикация не выполняются.

GitHub Actions сохраняется. Локальный hook является дополнительной проверкой и не заменяет удалённый CI.

---

## Рассмотренные варианты

### Проверять рабочую копию

Вариант отклонён.

Рабочая копия может содержать изменения, которые не входят в коммит. Результат проверки может не соответствовать подготовленному
состоянию.

### Выполнять проверки только перед push

Вариант отклонён.

Проверка перед push не предотвращает создание локального коммита с ошибками.

---

## Последствия

Для локального коммита требуется окружение, позволяющее выполнить проверки обеих частей проекта.

Время создания коммита увеличивается. Первый запуск может потребовать загрузки зависимостей и компонентов проверки.

Возможность частичного добавления изменений в индекс сохраняется.

Сценарии проверки должны обрабатывать ошибки команд и завершение выполнения без изменения пользовательских файлов.

Автоматические проверки должны покрывать успешное выполнение, ошибки проверок и соответствие снимку индекса при наличии
незастейдженных изменений.

Подключение hook и его запуск из терминала и IDE проверяются отдельно.

Локальный hook может быть отключён или обойдён средствами Git. Он не является механизмом защиты удалённой ветки.

---

## Не входит в решение

- Изменение поведения IntelliJ-плагина и прототипа VS Code;
- Изменение процесса публикации;
- Замена GitHub Actions;
- Выборочное сокращение проверок по изменённым файлам;
- Автоматическое исправление и добавление файлов в индекс.
