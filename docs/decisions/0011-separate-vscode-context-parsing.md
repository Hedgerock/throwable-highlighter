# ADR-0011: Выделение синтаксического разбора контекстов VS Code

## Статус

Принято.

---

## Контекст

`ThrowableHighlightingFinder` находит потенциальные Java-типы и определяет контекст их подсветки.

Контекст `THROWS` использует независимый `JavaThrowsClauseFinder`. Определение `CATCH` остаётся внутри `ThrowableHighlightingFinder` и
использует регулярное выражение до первой закрывающей круглой скобки.

Аннотация с аргументами нарушает границы параметра `catch`.

В выражении `catch (@Marker(IOException.class) IOException error)` ссылка внутри аргумента аннотации получает контекст `CATCH`,
а тип параметра — `CLASS`.

Обработка аннотаций и квалифицированных имён уже реализована для `THROWS`. Исправление `CATCH` требует аналогичного разбора
и независимой проверки граничных сценариев.

---

## Решение

Определение диапазонов типов в параметрах `catch` выделяется в компонент `JavaCatchClauseFinder`.

Компонент получает Java-код после обработки `JavaCodeMask` и не зависит от VS Code API, определения наследования, настроек
цветов и кэша.

Границы параметра определяются с учётом вложенных круглых скобок в аргументах аннотаций.

`JavaCatchClauseFinder` возвращает диапазоны имён типов одиночного `catch` и каждого типа multi-catch.

Ключевое слово `catch`, модификатор `final`, имя параметра, имена аннотаций, их аргументы и квалификаторы не включаются
в диапазоны типов контекста `CATCH`.

Ссылки на тип внутри аргументов аннотаций и тела блока сохраняют контекст `CLASS`.

Обработка аннотаций и выделение имён из квалифицированных ссылок выделяются в независимый компонент `JavaTypeReferenceRangeReader`.

`JavaCatchClauseFinder` и `JavaThrowsClauseFinder` используют общий компонент для чтения ссылок в пределах найденных
синтаксических конструкций. Правила определения границ `catch` и `throws` остаются в соответствующих компонентах.

`ThrowableHighlightingFinder` использует полученные диапазоны для выбора контекста.

Принадлежность типа к иерархии Throwable определяется существующим `JavaTypeDefinitionResolver`.

Поведение настроек цветов и контекста `THROWS` сохраняется.

---

## Рассмотренные варианты

### Усложнить регулярное выражение для параметра catch

Вариант отклонён.

Аргументы аннотаций могут содержать вложенные аннотации и круглые скобки. Определение границ требует учёта
вложенности.

### Продублировать обработку аннотаций из JavaThrowsClauseFinder

Вариант отклонён.

Исправления разбора аннотаций и квалифицированных ссылок потребуется независимо переносить между двумя реализациями.

### Выполнять весь разбор внутри ThrowableHighlightingFinder

Вариант отклонён.

Компонент зависит от VS Code API. Объединение поиска кандидатов и разбора синтаксических конструкций затрудняет независимую
проверку граничных сценариев.

---

## Последствия

Разбор параметров `catch` проверяется без запуска Extension Development Host.

Общие правила обработки аннотаций и квалифицированных ссылок проверяются отдельно и используются в двух контекстах.

Количество исходных файлов увеличивается. Синтаксический шаблон `CATCH_PARAMETER_PATTERN` удаляется из `ThrowableHighlightingContext`.

Автоматические проверки должны покрывать:

- одиночный `catch` и multi-catch;
- модификатор `final`;
- аннотации без аргументов и с вложенными аргументами;
- квалифицированные ссылки на типы;
- исключение имени параметра из диапазонов `CATCH`;
- сохранение позиций ссылок;
- отсутствие переноса диапазона незавершённого параметра в тело блока;
- сохранение существующего поведения `THROWS`.

Состояние реализации и известные ограничения обновляются в документации прототипа после проверки.

---

## Не входит в решение

- Изменение правил определения принадлежности типа к иерархии Throwable;
- Изменение fallback-набора и правил кэширования;
- Исправление контекста `IMPORT`;
- Исправление обработки text blocks в `JavaCodeMask`;
- Изменение настроек цветов;
- Создание общего исполняемого модуля для разных платформ;
- Полное семантическое разрешение Java-кода;
- Публикация расширения VS Code.
