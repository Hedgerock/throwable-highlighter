# ADR-0026: Локальные измерения ресурсов VS Code

## Статус

Принято.

---

## Контекст

Контролируемые измерения подтверждают сокращение повторных обращений после подключения планировщика.

По результатам ручного сравнения выбран интервал debounce 120 мс при максимальном ожидании 500 мс.

Потребление памяти, размер собственных кэшей и накопление незавершённых обращений требуют отдельных измерений.

Очистка кэша удаляет записи ожидающих результатов. Начатые обращения могут завершаться после смены поколения.

Размер карты ожидающих результатов не отражает все незавершённые обращения.

---

## Решение

Локальный режим измерения ресурсов включается при запуске Extension Host
переменной окружения `THROWABLE_HIGHLIGHTER_MEASURE_RESOURCES=1`.

### Память

Для процесса Extension Host фиксируются показатели process.memoryUsage():

- rss;
- heapUsed;
- heapTotal;
- external;
- arrayBuffers.

Значения сохраняются в байтах. Показатели рассматриваются отдельно и не суммируются.

Общая память Extension Host не приписывается целиком Throwable Highlighter. Память Java-сервера учитывается отдельно
средствами наблюдения за его процессом.

### Собственное состояние

Для resolver фиксируются:

- поколение кэша;
- количество сохранённых результатов определения типов;
- количество записей ожидающих результатов;
- количество незавершённых вызовов Definition Provider;
- количество незавершённых вызовов Document Symbol Provider;
- максимальное количество одновременных вызовов каждого вида за сеанс измерений.

Вызов команды учитывается от начала обращения до завершения возвращённого Promise.
При успешном завершении или ошибке счётчик незавершённых вызовов уменьшается.

Очистка кэша и смена поколения не обнуляют счётчики выполняющихся обращений.

Эти счётчики описывают вызовы команд со стороны расширения. Внутренняя работа Java-сервера измеряется отдельно.

### Сбор и запись

Периодический сбор выделяется в отдельный компонент. Resolver предоставляет снимок числовых показателей собственного состояния.

Снимок содержит идентификатор процесса и время от начала сеанса измерений. Период сбора фиксируется в методике прогона.

Максимальное потребление памяти определяется по полученным снимкам. Кратковременные пики между снимками могут оставаться
незарегистрированными.

Пики незавершённых обращений учитываются при изменении счётчиков независимо от периода сбора.

Записи направляются в существующий Output Channel с префиксом `[resource-measurement]`.

Компонент измерений не накапливает историю снимков. При выключенном режиме периодический сбор и запись не выполняются.

Освобождение компонента отменяет периодический сбор и прекращает запись.

---

## Последствия

Измерения позволяют сопоставить потребление памяти с размером кэша и количеством незавершённых обращений.

Методика прогона фиксирует исходное состояние после готовности Java, нагрузку и состояние после завершения повторных циклов
работы.

Автоматические проверки подтверждают учёт обращений при успешном завершении, ошибках и смене поколения, расчёт пиков и
освобождение компонента измерений.

Методика и результаты сохраняются в исследовании производительности.

---

## Не входит в решение

- Численные бюджеты памяти и времени;
- Ограничения размера кэшей и вытеснение записей;
- Ограничение параллельных обращений;
- Таймауты и отмена начатых команд;
- Пользовательская индикация состояния;
- Автоматическое профилирование Java-сервера;
- Передача измерений во внешние сервисы.
