# ADR-0001: Разделение контекстов подсветки

## Статус

Принято.

---

## Контекст

`ThrowableAnnotator` одновременно определяет тип PSI-элемента, разрешает ссылки, проверяет отношение типа к `Throwable` и
применяет подсветку.

Текущая реализация поддерживает три сценария:

- объявление класса;
- ссылка на класс;
- явный импорт класса.

Объявления и ссылки используют `THROWABLE_CLASS`.
Явные импорты используют `THROWABLE_IMPORT`, уровень `TEXT_ATTRIBUTES` и выделяют только имя импортируемого класса.

Добавление нового пользовательского контекста не должно приводить к дублированию проверки типа, выбора цветового ключа и
создания annotation.

---

## Решение

Контекст подсветки становится отдельной частью внутренней модели плагина.

Аннотатор разделяет обработку на следующие задачи:

1. Определение PSI-сценария.
2. Разрешение элемента в `PsiClass`.
3. Проверка, является ли тип `Throwable` или его наследником.
4. Выбор контекста подсветки.
5. Применение цветового ключа к заданному range.

Для каждого контекста явно определяются:

- цветовой ключ;
- severity;
- range подсветки.

Текущие контексты сохраняются без изменения поведения:

| Контекст                     | Цветовой ключ      | Severity          | Range                            |
|------------------------------|--------------------|-------------------|----------------------------------|
| Объявление или ссылка на тип | `THROWABLE_CLASS`  | `INFORMATION`     | Имя класса или ссылка            |
| Явный импорт                 | `THROWABLE_IMPORT` | `TEXT_ATTRIBUTES` | Только имя импортируемого класса |

Новый пользовательский контекст добавляется вместе с тестами, настройкой цвета при необходимости и обновлением
пользовательской документации.

---

## Рассмотренные варианты

### Сохранение текущей структуры `ThrowableAnnotator`

Вариант отклонён.

Текущая структура понятна при трёх сценариях, но при добавлении новых контекстов приведёт к повторению логики разрешения и
проверки типа.

### Отдельный annotator для каждого контекста

Вариант отклонён.

Контексты используют общую проверку типа. Разделение на несколько annotator увеличит количество extension registration без
достаточной пользы.

### Универсальная система правил подсветки

Вариант отклонён.

Плагин поддерживает ограниченное количество Java-контекстов. Обобщенная система правил увеличит сложность раньше появления
такой необходимости.

---

## Последствия

Рефакторинг не изменяет видимую пользовательскую функциональность.

Тесты должны фиксировать текущее поведение до изменения структуры кода.

Добавление нового контекста станет локальным изменением с явным набором требований.

В коде появится дополнительная внутренняя абстракция для контекста подсветки.

---

## Не входит в решение

- Добавление новых цветовых ключей;
- Изменение правил наследования цвета;
- Добавление поддержки Kotlin или других языков;
- Изменение проверки отношения типа к `Throwable`.
