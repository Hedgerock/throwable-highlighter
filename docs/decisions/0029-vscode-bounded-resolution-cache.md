# ADR-0029: Ограничение кэша результатов определения типов в VS Code

## Статус

Принято.

---

## Контекст

`JavaTypeDefinitionResolver` хранит подтверждённые результаты определения типов в памяти Extension Host. Ключ состоит из
URI документа, его версии и позиции ссылки.

В нагрузочных прогонах с лимитами Java-провайдеров 16 и 32 кэш достиг 420 записей. В обоих прогонах этот размер сохранялся
в течение заключительного ожидания после закрытия редактора.

Кэш накапливает записи в пределах поколения. Для продолжительной работы с разными файлами требуется верхняя граница числа
сохраняемых результатов.

---

## Решение

Для каждого экземпляра `JavaTypeDefinitionResolver` вводится предел числа записей в кэше подтверждённых результатов.

Лимит задаётся положительным целым числом. Значение для выпуска выбирается по результатам нагрузочных прогонов и фиксируется
в исследовании производительности.

Положительные и отрицательные подтверждённые результаты учитываются одинаково. При добавлении, обновлении или успешном чтении
запись становится последней использованной.

При добавлении нового ключа в заполненный кэш вытесняется запись, к которой дольше всего не обращались. Обновление существующего
ключа заменяет значение в той же записи.

После вытеснения следующее обращение к ключу запускает обычное разрешение типа. Вытеснение выполняется внутри текущего поколения.

Инвалидация очищает кэш и переводит resolver в следующее поколение. Подтверждённые результаты публикуются после проверки
актуальности поколения. `dispose()` освобождает записи вместе с остальным состоянием resolver.

Кэш подтверждённых результатов и карта незавершённых разрешений учитываются отдельно. Счётчик `cachedResolutionCount`
отражает фактическое число сохранённых записей.

Решение дополняет ADR-0006 ограничением ёмкости и правилом вытеснения.

---

## Последствия

Число записей в кэше ограничено выбранным пределом. При вытеснении возможны повторные обращения к Java-поддержке.

Автоматические проверки покрывают:

- соблюдение лимита после добавления нового ключа;
- вытеснение наименее недавно использованной записи;
- обновление порядка использования при чтении подтверждённого `false`;
- обновление существующего ключа без увеличения размера;
- повторное определение типа после вытеснения;
- очистку и соблюдение границ поколений.

В Extension Host проверяются повторные открытия при заполнении кэша и при нагрузке, превышающей его ёмкость.

Сравниваются число записей, время применения подсветки и память процессов. Бюджеты памяти определяются отдельно по результатам
измерений.

---

## Не входит в решение

- Ограничение длины очереди Java-провайдеров и карты незавершённых разрешений.
- Пользовательская настройка ёмкости кэша.
- Изменение правил определения Throwable и правил формирования ключей.
- Хранение кэша между запусками.
