# ADR-0017: Выборочная очистка результатов сборки прототипа VS Code

## Статус

Принято.

---

## Контекст

Прототип VS Code компилируется в каталоги `out` и `out-test`.

После переименования, перемещения или удаления исходного файла результаты предыдущей компиляции могут оставаться в выходном
каталоге.

Устаревшие JavaScript-файлы сохраняют прежнюю структуру сборки. Устаревшие тестовые файлы могут продолжать участвовать в
запуске тестов.

Выходной каталог может содержать файлы, которые не созданы компиляцией. Полная очистка каталога не сохраняет такие файлы.

Сборка включает компиляцию TypeScript и преобразование путей импортов через `tsc-alias`. Режим `watch` выполняет повторные
циклы при изменении исходников.

---

## Решение

Сборка прототипа дополняется учётом созданных файлов и выборочной очисткой устаревших результатов.

Результаты `tsconfig.json` и `tsconfig.test.json` учитываются раздельно в соответствующих выходных каталогах.

Для каждой конфигурации хранится локальный реестр созданных файлов. Реестр является служебным результатом сборки и не добавляется в Git.

В реестр включаются файлы, фактически записанные сборкой. Наличие файла в выходном каталоге само по себе не подтверждает
его принадлежность сборке.

Актуальный набор ожидаемых результатов определяется программой TypeScript и параметрами компиляции. Набор учитывает выходные
JavaScript-файлы, source maps и другие включённые результаты компиляции.

Устаревшими считаются зарегистрированные файлы, которые отсутствуют в актуальном наборе ожидаемых результатов.

Очистка выполняется после успешной компиляции и преобразования путей импортов.

При ошибке компиляции или преобразования импортов очистка не выполняется. Учёт файлов, фактически созданных неуспешной
попыткой, сохраняется для последующих сборок.

Очистка удаляет только зарегистрированные устаревшие файлы внутри соответствующего выходного каталога. Остальные файлы
сохраняются.

Пустые каталоги, оставшиеся после удаления учтённых файлов, могут удаляться в пределах выходного каталога.

При отсутствии реестра существующие файлы не признаются результатами сборки автоматически. Ранее накопившиеся остатки
проверяются отдельно.

Реестр проверяется перед использованием. Некорректный формат или выход зарегистрированного пути за границы выходного каталога
завершают сборку с ошибкой до удаления файлов.

Ошибка учёта или очистки считается ошибкой сборки.

Команды `compile`, `compile:test` и `watch` используют общие правила учёта и очистки.

В режиме `watch` используется полный набор ожидаемых результатов текущей программы TypeScript. Файлы, которые не пересобирались
в отдельном цикле, сохраняются, если они остаются частью актуальной программы.

Циклы сборки одного выходного каталога выполняются последовательно. Компиляция, преобразование импортов, учёт результатов
и очистка одного цикла завершаются до изменения результатов следующим циклом.

Преобразование импортов применяется к результатам компиляции. Файлы, которые не участвуют в сборке, сохраняются.

---

## Рассмотренные варианты

### Полностью удалять выходной каталог

Вариант отклонён.

Вместе с результатами компиляции удаляются файлы, которые не принадлежат сборке.

### Определить принадлежность файлов по расширению

Вариант отклонён.

Расширение `.js` или `.map` не подтверждает, что файл создан сборкой проекта. Такой подход не сохраняет посторонние файлы
с теми же расширениями.

---

## Последствия

Сценарий сборки координирует компиляцию, преобразование импортов, ведение реестра и очистку результатов.

Каталоги `out` и `out-test` получают служебные данные учёта.

Переименование, перемещение и удаление исходников отражаются в составе зарегистрированных результатов после успешной сборки.

Неучтённые файлы сохраняются независимо от расширения.

Автоматические проверки должны покрывать:

- переименование, перемещение и удаление исходных файлов;
- сохранение файлов, которые не принадлежат сборке, включая файлы с расширениями `.js` и `.map`;
- удаление связанных source maps;
- независимость результатов основной и тестовой конфигураций;
- сохранение актуальных файлов при частичной пересборке в `watch`;
- отсутствие очистки при ошибке компиляции или преобразования импортов;
- учёт файлов, созданных неуспешной попыткой;
- первый запуск без реестра;
- некорректный реестр и нарушение границ выходного каталога;
- ошибки записи реестра и удаления файлов;
- последовательное выполнение повторных циклов сборки.

Состояние реализации и порядок первоначальной проверки выходных каталогов фиксируются в документации прототипа.

---

## Не входит в решение

- Изменение IntelliJ-плагина;
- Изменение определения Java-типов, контекстов подсветки и настроек цветов;
- Автоматическое удаление файлов с неподтверждённой принадлежностью сборке;
- Внедрение бандлера или универсальной системы сборки;
- Изменение правил публикации и поддержки VS Code.
