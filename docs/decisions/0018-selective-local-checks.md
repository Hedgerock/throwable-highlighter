# ADR-0018: Выбор локальных проверок по изменённым файлам

## Статус

Принято.

---

## Контекст

Проект содержит IntelliJ-плагин и технический прототип VS Code.

Согласно ADR-0016 перед каждым коммитом выполняются проверки обеих частей проекта независимо от состава изменений.

Изменения только в документации запускают Gradle, установку npm-зависимостей и проверки прототипа. Изменения одной платформы
требуют выполнения проверок другой платформы.

Локальная проверка форматирования прототипа обрабатывает весь доступный набор файлов.

GitHub Actions выполняет полный набор проверок проекта.

---

## Решение

Локальные проверки выбираются по составу изменённых файлов.

Определение изменённых файлов, построение плана проверок и выполнение команд разделяются. Правила выбора проверяются независимо
от запуска Gradle, npm и Prettier.

### Проверка подготовленного коммита

Для `pre-commit` учитываются только изменения индекса Git относительно `HEAD`. При отсутствии `HEAD` учитываются все файлы,
добавленные в индекс.

Список изменений определяется в исходном репозитории до выгрузки снимка. Для определения изменений и подготовки снимка
используется один и тот же индекс, включая индекс, переданный через `GIT_INDEX_FILE`.

Проверки выполняются во временном снимке индекса согласно ADR-0016. Незастейдженные и неотслеживаемые файлы рабочей копии
не участвуют в проверке коммита.

Состав проверок определяется следующими правилами:

| Изменения                                                    | Проверки                                           |
|--------------------------------------------------------------|----------------------------------------------------|
| Только явно определённая текстовая документация              | Без проверок платформ и установки npm-зависимостей |
| Код, тесты, ресурсы или конфигурация сборки IntelliJ-плагина | Проверки IntelliJ-плагина                          |
| Код, тесты, ресурсы или конфигурация прототипа VS Code       | Проверки прототипа VS Code                         |
| Обе платформы                                                | Проверки обеих платформ                            |
| Общие fixtures или инфраструктура проверок                   | Проверки обеих платформ                            |
| Путь без определённого правила                               | Проверки обеих платформ                            |

К общей инфраструктуре относятся hook, механизм локальных проверок, workflow CI и общие настройки репозитория, влияющие на
подготовку проверяемого состояния.

Правила документации задаются явно. Принадлежность к каталогу `docs` сама по себе не исключает файл из проверок. Общие
fixtures не считаются только текстовой документацией.

Для смешанного набора изменений объединяются все необходимые группы проверок.

Удаление файла запускает проверки соответствующей части проекта. При переименовании учитываются старый и новый пути.

Тесты механизма локальной проверки выполняются перед каждым коммитом независимо от выбранных платформ.

Для выбранной платформы компиляция, тесты и проверка сборки выполняются полностью. Выбор отдельных тестов по изменённым
исходным файлам не вводится.

### Проверка форматирования

Обычная локальная проверка форматирования учитывает изменения рабочей копии и индекса относительно `HEAD`. Проверяется
текущее содержимое файлов рабочей копии.

Неотслеживаемые файлы исключаются. Новые файлы включаются после добавления в индекс.

В `pre-commit` проверяется содержимое изменённых файлов из снимка индекса.

В Prettier передаются только существующие файлы прототипа с поддерживаемым форматом. Правила `.prettierignore` сохраняются.
Удалённые файлы не передаются форматтеру.

При отсутствии подходящих файлов проверка форматирования завершается успешно без запуска Prettier.

Изменение конфигурации форматирования, `package.json` или lockfile прототипа запускает полную проверку форматирования
отслеживаемых файлов прототипа.

Форматирование выполняется в режиме проверки. Рабочие файлы и индекс автоматически не исправляются.

### Полный прогон

Полный набор проверок остаётся доступным для явного локального запуска.

GitHub Actions сохраняет полный прогон обеих платформ и форматирования независимо от состава изменений.

Ошибка получения списка изменений, подготовки снимка или выбранной проверки завершает hook с ненулевым кодом. Ошибка определения
изменений не считается отсутствием изменений.

Решение изменяет правило ADR-0016 об обязательной проверке обеих частей перед каждым коммитом. Локальный набор проверок
выбирается по изменениям и может быть меньше полного набора CI.

Остальные положения ADR-0016 сохраняют силу.

---

## Рассмотренные варианты

### Сохранить полный прогон перед каждым коммитом

Вариант отклонён.

Изменения документации и одной платформы продолжают запускать проверки незатронутых частей проекта.

### Запускать только тесты изменённых файлов

Вариант отклонён.

Изменение компонента может влиять на другие компоненты и их тесты. Полный набор проверок выбранной платформы сохраняет
проверку этих связей.

---

## Последствия

Для документационных коммитов не требуется запуск Gradle и установка npm-зависимостей.

Требования к JDK и npm зависят от выбранных проверок. Git и Node.js остаются необходимыми для запуска hook.

Механизм локальной проверки получает явные правила классификации путей и построения плана. Новые каталоги учитываются отдельными
правилами; до их добавления используется полный прогон.

Автоматические проверки должны покрывать:

- изменения только документации;
- изменения одной и обеих платформ;
- общие fixtures, инфраструктуру и неизвестные пути;
- добавление, удаление и переименование файлов;
- смешанный набор изменений;
- отсутствие `HEAD` и пустой набор изменений;
- различие рабочей копии и индекса, включая частичное добавление файла;
- использование переданного индекса Git;
- исключение неотслеживаемых, удалённых, игнорируемых и неподдерживаемых файлов из форматирования;
- полный прогон форматирования при изменении его конфигурации или зависимостей;
- имена файлов с пробелами и другими специальными символами;
- явный полный режим;
- ошибки определения изменений и выполнения команд;
- сохранение рабочей копии и индекса.

Состав команд и актуальные правила путей описываются в документации локальных проверок после реализации.

---

## Не входит в решение

- Изменение поведения IntelliJ-плагина и прототипа VS Code;
- Выбор отдельных тестов внутри платформы;
- Сокращение удалённых проверок CI;
- Изменение процесса публикации;
- Автоматическое исправление форматирования и добавление файлов в индекс.
