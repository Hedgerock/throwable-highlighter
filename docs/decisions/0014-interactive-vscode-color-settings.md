# ADR-0014: Интерактивная настройка цветов в VS Code

## Статус

Принято.

---

## Контекст

Прототип VS Code предоставляет отдельные строковые настройки цветов для контекстов `CLASS`, `IMPORT`, `CATCH` и `THROWS`.

Пустое значение `classColor` сохраняет стандартную Java-подсветку. Пустые значения остальных цветов наследуют `CLASS`.

Текущая модель не позволяет явно выбрать стандартную Java-подсветку для производного контекста, если для `CLASS` задан
собственный цвет.

Roadmap определяет интерактивную настройку цветов как обязательную итерацию перед первым публичным выпуском VS Code.

Для выполнения этого требования необходимо разделить источник цвета и его собственное значение.

---

## Решение

В расширение добавляется команда открытия панели настройки цветов на основе VS Code Webview API.

Панель предоставляет настройку контекстов `CLASS`, `IMPORT`, `CATCH` и `THROWS`.

Для `CLASS` доступны два источника:

- собственный цвет;
- стандартная Java-подсветка.

Для `IMPORT`, `CATCH` и `THROWS` доступны три источника:

- собственный цвет;
- наследование от `CLASS`;
- стандартная Java-подсветка.

Наследование `CLASS` от самого себя не допускается. Произвольный выбор родительского контекста не вводится.

Собственный цвет задаётся визуальным выбором или текстовым вводом.

Наследование использует результат разрешения цвета `CLASS`. Если `CLASS` сохраняет стандартную Java-подсветку, наследующий
контекст не получает foreground-decoration.

Выбор стандартной Java-подсветки отключает foreground-decoration для соответствующего контекста независимо от цвета `CLASS`.
Расширение не вычисляет и не копирует стандартный цвет Java из активной темы.

Источник цвета хранится отдельно от собственного значения. Переключение источника не удаляет сохранённый собственный цвет.

Существующие настройки `classColor`, `importColor`, `catchColor` и `throwsColor` сохраняются. При отсутствии явно заданного
источника применяются прежние правила обработки пустых и непустых значений.

Панель использует конфигурацию VS Code как источник сохранённых настроек. Отдельное хранилище цветов в webview не создаётся.

Область сохранения выбирается явно: `User` или `Workspace`. При отсутствии открытой рабочей области доступна только `User`.

Панель различает настройки выбранной области и эффективные значения с учётом приоритетов конфигурации VS Code. Изменение одной
области не перезаписывает настройки другой.

До применения изменения остаются черновиком. Закрытие панели без применения не изменяет конфигурацию.

Перед сохранением расширение проверяет полученные данные. Некорректный источник или значение цвета не сохраняются.

После успешного сохранения подсветка обновляется без перезапуска Extension Development Host.

Разрешение источника и итогового цвета выделяется в отдельный компонент, независимый от webview и VS Code API. Decoration
controller использует результат этого компонента.

Webview использует ограничительную Content Security Policy и не загружает сетевые ресурсы. Данные из сообщений и настроек
проверяются на стороне расширения перед использованием.

Определение Java-типов, выбор контекстов, обход иерархии и кэширование не изменяются.

Решение дополняет модель настройки цветов VS Code, описанную в ADR-0010. При отсутствии явно заданного источника прежнее
поведение сохраняется. Остальные положения связанных решений сохраняют силу.

---

## Рассмотренные варианты

### Сохранить только стандартный Settings UI

Вариант отклонён.

Строковые настройки не предоставляют единый интерфейс визуального выбора цвета и источника для четырёх контекстов.

### Использовать последовательность Quick Pick и Input Box

Вариант отклонён.

Последовательные диалоги разделяют выбор контекста, источника и значения. Пользователь не видит настройки всех контекстов
одновременно.

### Обозначить источник специальным значением цветовой строки

Вариант отклонён.

Одна настройка будет одновременно представлять цвет и правило его получения. Разделение источника и значения сохраняет
собственный цвет при переключении режима.

---

## Последствия

Расширение получает отдельную панель настройки цветов и явную модель источников цвета.

Логика разрешения цвета проверяется независимо от интерфейса и decoration controller.

Автоматические проверки должны покрывать:

- допустимые источники для каждого контекста;
- собственный цвет и наследование от `CLASS`;
- стандартную Java-подсветку при заданном собственном цвете `CLASS`;
- сохранение прежнего поведения существующих настроек;
- сохранение собственного значения при переключении источника;
- области сохранения и приоритеты конфигурации;
- отклонение некорректных данных;
- отсутствие сохранения при закрытии неприменённого черновика;
- обновление подсветки после применения настроек.

Визуальный выбор цвета, работу с клавиатурой и отображение панели в разных темах необходимо проверить в Extension Development
Host.

Состояние реализации и известные ограничения обновляются в документации после проверки.

Реализация интерфейса не переводит VS Code из статуса технического прототипа в поддерживаемую пользовательскую платформу.

---

## Не входит в решение

- Произвольные цепочки наследования цветов между контекстами;
- Изменение правил определения Throwable;
- Добавление контекстов подсветки;
- Изменение IntelliJ-плагина;
- Создание общего исполняемого модуля;
- Публикация расширения и принятие публичной поддержки VS Code.
