# ADR-0025: Локальные замеры обновления подсветки VS Code

## Статус

Принято.

---

## Контекст

Контролируемый стенд показывает снижение числа повторных обращений
после подключения планировщика.

Замер resolver в Extension Host фиксирует длительность определения одного типа.
Для оценки задержек планировщика требуется измерение полного пути обновления
с настоящей Java-поддержкой.

---

## Решение

Локальный режим замеров включается при запуске Extension Host
переменной окружения `THROWABLE_HIGHLIGHTER_MEASURE_REFRESH=1`.

Для применённого обновления в каждом редакторе фиксируются три момента:

- получение последнего запроса обновления;
- запуск обработки видимых редакторов планировщиком;
- возврат из последнего вызова `setDecorations()` для этого редактора.

Для изменения текста начальный момент фиксируется в обработчике события
перед очисткой кэша. При объединении запросов используется время и причина
последнего запроса, вошедшего в запуск.

Режим записи соответствует фактическому режиму запуска планировщика.
Последующий отложенный запрос обновляет время и причину,
сохраняя срочность уже запланированного запуска.

Из этих моментов вычисляются время до запуска, время обработки редактора
и общая длительность обновления. Для измерений используются монотонные часы.

Запись содержит поколение обновления, причину запроса, режим запуска,
номер редактора в текущем запуске и длительности. Записи направляются
в существующий Output Channel. В журнал включаются только перечисленные поля.

Результаты, отброшенные по правилам актуальности или после dispose,
пропускаются при записи применённых обновлений.

Первый замер выполняется на одном видимом Java-редакторе после готовности сервера.
Одиночные правки и серии правок фиксируются отдельно.

---

## Последствия

Результаты позволяют сравнить вклад ожидания запуска и обработки редактора
при подборе интервалов планировщика.

Автоматические проверки подтверждают расчёт длительностей,
выбор последнего запроса и отсутствие записей для отброшенных результатов.

Методика запуска и результаты фиксируются в исследовании производительности.

---

## Не входит в решение

- Индикация состояния и уведомления;
- Измерение отрисовки на экране;
- Численные бюджеты задержки и памяти;
- Ограничение выполняющихся обращений;
- Передача диагностических данных во внешние сервисы.
