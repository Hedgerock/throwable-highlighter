# ADR-0022: Восстановление подсветки после запуска Java-поддержки VS Code

## Статус

Принято.

---

## Контекст

Прототип разрешает Java-типы через Definition Provider.

При холодном старте Java-поддержка может быть недоступна во время первоначального
обновления подсветки.

После активации выполняются дополнительные обновления через одну, три и восемь секунд.
Эти интервалы не определяют фактическую готовность Java-сервера.

Ручная проверка межфайлового транзитивного наследования выявила отсутствие подсветки
после запуска. Переключение на другой файл инициирует обновление и восстанавливает подсветку.

Для восстановления требуется обновление после готовности Java-поддержки без действий пользователя.

---

## Решение

Первоначальное восстановление подсветки интегрируется с установленным расширением
Language Support for Java by Red Hat (`redhat.java`).

Для ожидания готовности стандартного Java-сервера используется публичный метод
`serverReady()` экспортируемого API расширения.

Получение API и ожидание готовности выполняются асинхронно и не блокируют
активацию Throwable Highlighter.

Первоначальное обновление видимых редакторов сохраняется.

После подтверждения готовности Java-сервера расширение очищает кэш определения типов
и запускает обновление видимых редакторов.

Сброс кэша выполняется перед обновлением подсветки.

Готовность сервера является основанием для повторной проверки ссылок.
Она не подтверждает принадлежность отдельного типа к Throwable.

Проверка объявлений, обработка `confirmed` и `unavailable`, обход иерархии
и выбор контекстов сохраняют существующие правила.

Ожидание готовности выделяется в отдельный компонент VS Code-интеграции.
Компонент не определяет Java-типы и не управляет цветовыми настройками.

Фиксированные стартовые обновления по таймерам удаляются.

Отсутствие расширения, недоступность необходимого API или ошибка ожидания
не прерывают активацию Throwable Highlighter.

До подтверждения типов сохраняется стандартная Java-подсветка.
Ошибки интеграции записываются в существующий Output Channel.

После освобождения компонента завершение асинхронного ожидания не очищает кэш
и не запускает обновление редакторов.

Решение дополняет правила инвалидирования ADR-0006 событием готовности Java-сервера.
Остальные положения связанных решений сохраняют силу.

---

## Рассмотренные варианты

### Увеличить интервалы стартовых обновлений

Вариант отклонён.

Время запуска зависит от окружения и рабочей области.
Фиксированный набор задержек не подтверждает готовность Java-сервера.

### Периодически повторять разрешение типов

Вариант отклонён.

Периодический опрос создаёт дополнительные запросы и требует отдельных правил остановки.
Недоступность отдельного определения не означает, что Java-сервер продолжает запускаться.

---

## Последствия

Прототип получает явную интеграцию с готовностью стандартного сервера `redhat.java`.

Восстановление подсветки после его запуска не требует переключения редактора
или изменения документа.

Автоматические проверки покрывают:

- уже готовый Java-сервер;
- готовность после завершения прежних стартовых интервалов;
- очистку кэша перед обновлением видимых редакторов;
- отсутствие расширения и недоступность API;
- отклонённое ожидание готовности;
- завершение ожидания после освобождения компонента;
- сохранение неблокирующей активации расширения.

Ручная проверка повторяет холодный запуск межфайлового сценария без переключения редактора.

При подготовке публичного выпуска поддерживаемое Java-расширение и режим сервера
фиксируются в требованиях совместимости.

---

## Не входит в решение

- Поддержка сигналов готовности других Java-расширений;
- Поддержка готовности сервера в режиме `LightWeight`;
- Отслеживание повторных запусков Java-сервера в пределах одной сессии;
- Изменение правил определения Throwable и обхода иерархии;
- Изменение ключа кэша и объединения незавершённых запросов;
- Добавление контекстов и настроек подсветки;
- Изменение IntelliJ-плагина;
- Публичный выпуск расширения VS Code.
