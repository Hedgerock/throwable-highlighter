# ADR-0007: Определение транзитивных наследников Throwable в прототипе VS Code

## Статус

Принято.

---

## Контекст

[ADR-0005](0005-vscode-direct-throwable-inheritance.md) определил поддержку пользовательских классов, которые напрямую
наследуют известный тип Throwable.

Текущий `JavaTypeDefinitionResolver` не определяет пользовательский тип, если его непосредственный родитель также является
пользовательским классом.

Например, `CustomException` не считается целевым типом, если он наследует `BaseException`, а `BaseException` напрямую наследует
`RuntimeException`.

[ADR-0006](0006-cache-vscode-type-resolution.md) добавил кэширование подтверждённых результатов определения типов и правила
его инвалидирования.

Прототипу требуется определить ограниченный способ обхода пользовательской цепочки наследования без использования
недокументированных API Java-расширений VS Code.

---

## Решение

`JavaTypeDefinitionResolver` рекурсивно определяет прямого родителя пользовательского класса до достижения известного
стандартного типа Throwable или подтверждённого нецелевого типа.

Для каждого пользовательского класса resolver получает определение его прямого родителя через `vscode.executeDefinitionProvider`
и проверяет объявление найденного класса.

Тип считается целевым, если любая проверенная ступень его цепочки наследования напрямую наследует известный стандартный
тип Throwable.

Известные стандартные типы Throwable продолжают определяться без вызова Definition Provider.

Обход использует идентификатор объявления класса, состоящий из URI документа и диапазона определения. Повторное посещение
того же объявления прекращает обход и возвращает недоступный результат.

Количество переходов между родительскими классами ограничивается шестнадцатью. Превышение ограничения возвращает недоступный
результат.

Отсутствие результата Definition Provider, ошибка команды, недоступность документа определения, неопределённый прямой родитель,
цикл или превышение глубины не считаются подтверждённым отрицательным результатом.

Такие результаты не сохраняются в кэше и не изменяют стандартную Java-подсветку.

Подтверждённые положительные и отрицательные результаты используют существующий кэш в памяти Extension Host согласно
[ADR-0006](0006-cache-vscode-type-resolution.md).

---

## Рассмотренные варианты

### Сохранить только прямое наследование

Вариант отклонён.

Подход не определяет обычную цепочку пользовательских исключений и ограничивает практическую ценность прототипа.

### Выполнять неограниченный рекурсивный обход

Вариант отклонён.

Неполный Java-код, некорректные определения или неожиданные результаты Definition Provider не должны создавать неограниченные
асинхронные запросы.

### Считать недоступное определение нецелевым типом

Вариант отклонён.

Во время запуска Java-поддержки или обработки изменений Definition Provider может временно не вернуть определение
существующего класса. Такой результат не подтверждает отсутствие наследования Throwable.

---

## Последствия

Прототип определяет пользовательские классы с транзитивным наследованием от известных стандартных типов Throwable.

Первая проверка длинной цепочки наследования может потребовать нескольких асинхронных вызовов Definition Provider.

Повторные проверки используют существующий кэш подтверждённых результатов, пока не произошло изменение документов или файлов
рабочей области.

Для реализации потребуются fixtures с пользовательской цепочкой из двух и более классов, а также проверки цикла, превышения
глубины и временно недоступного определения.

---

## Не входит в решение

- Поддержка интерфейсов, `enum`, `record` и других форм Java-типов;
- Полное синтаксическое или семантическое разрешение Java-кода;
- Неограниченный обход иерархии;
- Кэширование между запусками VS Code;
- Изменение правил подсветки IntelliJ-плагина;
- Поддержка VS Code как пользовательской платформы;
- Создание Language Server Protocol сервера.
