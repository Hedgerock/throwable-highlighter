# ADR-0039: Разделить контексты, категории и оформление IntelliJ-подсветки

**Область действия** — IntelliJ Platform

## Статус

Принято.

---

## Контекст

Плагин IntelliJ Platform различает пять контекстов подсветки. Для `CLASS` и `CATCH` поддерживаются категории `CHECKED`,
`RUNTIME_EXCEPTION` и `ERROR`.

Страница цветовой схемы содержит одиннадцать настроек. Базовые атрибуты контекстов и атрибуты категорий отображаются общим списком.

`ThrowableCategory` хранит отдельные имена и ключи для `CLASS` и `CATCH`. Поддержка категорий дополнительно перечисляется
в аннотаторе и странице цветовой схемы. Расширение оформления требует согласованных изменений в нескольких компонентах.

Требуется разделить определение контекста, классификацию типа и описание оформления, а настройки цветовой схемы сгруппировать по контекстам.

---

## Решение

### Разделение ответственности

`ThrowableHighlightingContext` представляет место применения подсветки.
Сохраняются контексты `CLASS`, `IMPORT`, `CATCH`, `THROWS` и `JAVADOC`,
их severity и подписи для выбора источника.

`ThrowableCategory` представляет категорию разрешённого Java-типа. Перечисление содержит `CHECKED`, `RUNTIME_EXCEPTION` и `ERROR`.
Описание цветовых ключей и элементов интерфейса переносится в каталог оформления.

`ThrowableTypeClassifier` определяет категорию типа по существующим правилам.

`ThrowableHighlighting` сохраняет объявления цветовых ключей и их fallback-связи.

### Каталог оформления

Компонент `ThrowableHighlightingStyles` содержит неизменяемые описания оформления для поддерживаемых контекстов.

Описание контекста включает:

- базовый цветовой ключ;
- названия элементов и групп страницы цветовой схемы;
- оформление поддерживаемых категорий;
- соответствие тегов предпросмотра цветовым ключам.

Для `CLASS` и `CATCH` описываются все три категории.
Для `IMPORT`, `THROWS` и `JAVADOC` используется базовое оформление контекста.

Каталог является единым источником сопоставления контекста и категории с оформлением. Аннотатор использует его для выбора ключа.
Страница цветовой схемы получает из тех же описаний дескрипторы и соответствия тегов.

Проверка выбранного источника предшествует классификации типа. Классификация выполняется для контекстов с категорийным оформлением.
Для остальных контекстов сохраняется проверка принадлежности типа к `Throwable`.

Неразрешённый тип или отсутствие подтверждённого наследования `Throwable` завершает обработку без аннотации.

### Группировка настроек

В разделе `Settings | Editor | Color Scheme | Throwable Highlighter`
используется следующая структура:

```text
Throwable Highlighter
├─ Class
│  ├─ Base attributes
│  ├─ Checked
│  ├─ Runtime exception
│  └─ Error
├─ Catch
│  ├─ Base attributes
│  ├─ Checked
│  ├─ Runtime exception
│  └─ Error
├─ Import
├─ Throws
└─ Javadoc
```

Группировка задаётся штатным механизмом `ColorSettingsPage`
через пути в именах `AttributesDescriptor`, например `Class//Checked`.

`Class//Base attributes` соответствует `THROWABLE_CLASS`.
`Catch//Base attributes` соответствует `THROWABLE_CATCH`.

Группы представляют контексты. Наследование атрибутов определяется fallback-связями ключей.

### Совместимость

Сохраняются все одиннадцать цветовых ключей, их внешние имена, настроенные атрибуты и существующие теги предпросмотра.

Ключи категорий `CLASS` наследуют атрибуты `THROWABLE_CLASS`.
Ключи категорий `CATCH` наследуют атрибуты `THROWABLE_CATCH`.
Базовые ключи `IMPORT`, `CATCH`, `THROWS` и `JAVADOC` наследуют атрибуты `THROWABLE_CLASS`.

Источник выбирается независимо для каждого из пяти контекстов.
В форме `Settings | Tools | Throwable Highlighter` сохраняются подписи источника плагина: `Throwable class`, `Throwable import`,
`Throwable catch`, `Throwable throws` и `Throwable Javadoc`.

Подписи источников отделяются от названий элементов сгруппированной цветовой схемы. Формат сохранения источников и загрузка
прежнего выбора `CATCH` сохраняются.

Решение уточняет представление цветовых настроек из ADR-0037 и ADR-0038, а также связь подписей источников с элементами
цветовой схемы из ADR-0028. Остальные положения этих решений сохраняют силу.

## Последствия

Добавление оформления категории выполняется через описание соответствующего контекста в каталоге. Перечисление категорий
сохраняет ответственность за модель классификации.

Страница цветовой схемы сохраняет одиннадцать редактируемых настроек и показывает принадлежность категорий к контекстам.

Регрессионные проверки покрывают:

- выбор прежних ключей для всех поддерживаемых контекстов и категорий;
- сохранение диапазонов и severity аннотаций;
- независимость источников подсветки;
- полноту и уникальность дескрипторов цветовой схемы;
- соответствие групп и названий существующим ключам;
- соответствие тегов предпросмотра дескрипторам;
- восстановление сохранённых атрибутов и прежние цепочки наследования.

Группировка, выбор атрибутов через предпросмотр и применение цветов проверяются вручную в sandbox IntelliJ Platform.

Документация по архитектуре и настройкам обновляется после реализации.

---

## Не входит в решение

- Добавление контекстов, категорий или цветовых ключей.
- Изменение правил классификации Java-типов.
- Изменение диапазонов подсветки или severity.
- Изменение источников подсветки и их формата хранения.
- Оптимизация PSI-разрешения и кэширования.
- Создание собственного редактора цветовой схемы.
- Изменения расширения VS Code.
