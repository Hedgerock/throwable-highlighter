# ADR-0031: Проверка бюджетов производительности VS Code перед выпуском

## Статус

Принято.

---

## Контекст

Для прототипа выбраны пределы параллельных команд Java-провайдеров, размера кэша и
незавершённых определений типов. Нагрузочные прогоны содержат замеры времени применения
подсветки и снимки памяти Extension Host и Java-сервера.

Для проверки перед выпуском требуется воспроизводимый сценарий с численными пределами
и правилом подтверждения превышений.

---

## Решение

Бюджеты проверяются в контрольном окружении по
[нагрузочному сценарию со 100 типами](../research/vscode-performance.md#нагрузочный-прогон-со-100-типами).
Перед измерением подтверждается готовность стандартного Java-сервера. Сценарий включает
первые открытия `Usage010`, `Usage050` и `Usage100`, три повторных цикла и заключительную
минуту с закрытыми Java-редакторами.

Для каждого прогона фиксируются коммит, версии VS Code, `redhat.java` и Java, параметры
рабочей области, состав расширений и пределы контроллера, кэша и Java-провайдеров.

Бюджет времени применяется к `totalMs` первого открытия `Usage100` и медиане трёх
повторных открытий этого файла. Бюджет памяти применяется к максимальному RSS
Extension Host и максимальному Working Set Java среди снимков окна измерения.
Показатели памяти проверяются отдельно для каждого процесса.

Первоначальные значения подтверждаются, если каждый показатель укладывается в свой предел
во всех трёх сопоставимых прогонах. Для сравнения используются прогоны с завершённым окном
измерения, снимками обоих процессов и замерами первого и трёх повторных открытий `Usage100`.
Принятые пределы, условия измерения и ссылки на архивы фиксируются в исследовании
производительности.

Перед выпуском контрольный сценарий выполняется на сборке, подготовленной к выпуску.
При превышении предела выполняется повторный прогон той же сборки в том же окружении.
Повторное превышение по тому же показателю считается подтверждённым и устраняется до выпуска.

---

## Последствия

Проверка даёт сопоставимые результаты для контрольного окружения и выбранного набора
файлов. Снимки памяти описывают процессы целиком с периодом измерения в одну секунду.

Сценарии редактирования, переключения редакторов и нескольких видимых Java-файлов
проверяются отдельно в рамках предрелизных проверок.

---

## Не входит в решение

- Универсальные пределы времени и памяти для всех рабочих областей.
- Оценка доли памяти, используемой непосредственно Throwable Highlighter.
- Автоматическая проверка бюджетов в CI.
- Пользовательская индикация длительного ожидания подсветки.
