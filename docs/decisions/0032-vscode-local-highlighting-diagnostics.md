# ADR-0032: Локальная диагностика подсветки VS Code

## Статус

Принято.

---

## Контекст

Время появления подсветки зависит от готовности Java-поддержки и обработки типов в видимых редакторах. Пользователю требуется
информация о текущем этапе работы расширения и доступ к локальному журналу.

Измерительные прогоны используют отдельный формат записей для последующей обработки.

---

## Решение

Состояние Throwable Highlighter отображается в Language Status для активного Java-документа со схемой `file`. Из статуса и
палитры команд доступна команда `Open Diagnostics`, которая открывает канал `Throwable Highlighter Diagnostics`.

| Состояние                    | Условие                                                                            |
|------------------------------|------------------------------------------------------------------------------------|
| `Waiting for Java`           | Выполняется первоначальная проверка готовности стандартного Java-сервера.          |
| `Java readiness unconfirmed` | Проверка завершилась без подтверждения готовности.                                 |
| `Updating highlighting`      | Актуальное обновление активного файла продолжается спустя 2 секунды после запроса. |
| `Highlighting update failed` | Контроллер обнаружил сбой подготовки или применения актуального обновления.        |
| `Ready`                      | Готовность Java подтверждена, подсветка работает в обычном режиме.                 |

Приоритет отображения имеет ошибка актуального обновления, затем ожидание Java и длительное обновление. В остальных случаях 
отображается результат проверки готовности Java. Отсутствие подтверждённого Throwable и выбор стандартной подсветки
относятся к обычным результатам обработки.

Таймер длительного обновления привязан к активному документу и поколению обновления. Завершение, замена обновления, смена
активного редактора и освобождение расширения сбрасывают таймер. Состояние обновляется по событиям актуального поколения.

Журнал содержит этап, результат, длительность и доступные счётчики при ожидании, длительном обновлении и сбое. Для событий
используются заранее определённые категории сообщений. В журнал записываются только диагностические данные расширения
без исходного текста, путей, имён типов и стека исключений.

Диагностический журнал ведётся локально. Обычные обновления подсветки проходят без уведомлений. Диагностические записи и
журналы нагрузочных измерений выводятся в разные каналы.

Запись ошибок первоначальной проверки готовности Java направляется в`Throwable Highlighter Diagnostics`. Это уточняет правило
вывода ошибок из [ADR-0022](0022-vscode-java-readiness.md).

---

## Последствия

Пользователь видит состояние подсветки в контексте активного Java-файла и открывает подробности по запросу.

Автоматические проверки покрывают переходы состояния, срабатывание порога, замену поколения, смену редактора и освобождение таймера.
Отображение статуса и открытие журнала проверяются в Extension Development Host.

---

## Не входит в решение

- Отправка диагностических данных во внешние сервисы.
- История измерений, экспорт и отчёт производительности.
- Настройка порога длительного обновления пользователем.
- Изменение правил определения типов и бюджетов производительности.
