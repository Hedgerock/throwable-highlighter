# ADR-0012: Выделение синтаксического разбора импортов VS Code

## Статус

Принято.

---

## Контекст

`ThrowableHighlightingFinder` находит потенциальные Java-типы и определяет контекст их подсветки.

Разбор параметров `catch` и списков `throws` выделен в независимые компоненты согласно ADR-0011.

Определение `IMPORT` остаётся внутри `ThrowableHighlightingFinder` и использует начало текущей строки.

Такой подход связывает границы импорта с форматированием исходного текста. Многострочные импорты и несколько конструкций
на одной строке могут получить неверный контекст.

В wildcard import вложенных типов имя внешнего класса может ошибочно обрабатываться как импортируемый тип.

Для исключения ложной подсветки необходимо различать диапазон всего объявления импорта и диапазон имени импортируемого типа.

---

## Решение

Синтаксический разбор объявлений импорта выделяется в компонент `JavaImportClauseFinder`.

Компонент получает Java-код после обработки `JavaCodeMask` и не зависит от VS Code API, определения наследования, настроек
цветов и кэша.

`JavaImportClauseFinder` определяет диапазоны объявлений импорта и отдельно возвращает диапазон конечного имени типа для
завершённого явного нестатического импорта.

Границы завершённого объявления определяются от ключевого слова `import` до точки с запятой. Переносы строк и комментарии
между частями имени не изменяют выбор контекста.

В квалифицированном имени импортируемого типа обрабатывается только конечный идентификатор. Имена пакетов и внешних типов
не включаются в целевой диапазон.

Wildcard imports, включая импорты вложенных типов, не формируют целевой диапазон. Существующее исключение статических импортов
из подсветки прототипа сохраняется.

`ThrowableHighlightingFinder` использует диапазон объявления для исключения остальных идентификаторов импорта из обработки.
Квалификаторы и содержимое исключённых импортов не переходят в контекст `CLASS`.

За пределами объявления импорта выбор контекста выполняется по существующим правилам.

Незавершённый импорт не формирует целевой диапазон. Его разбор не должен захватывать последующие объявления и тела блоков.

Принадлежность типа к иерархии Throwable определяется существующим `JavaTypeDefinitionResolver`.

Набор контекстов, настройки цветов и правила их наследования сохраняются.

---

## Рассмотренные варианты

### Сохранить определение импорта по началу строки

Вариант отклонён.

Строка исходного текста не определяет границы Java-импорта. Усложнение построчной проверки сохраняет зависимость от
форматирования.

### Возвращать только диапазоны имён импортируемых типов

Вариант отклонён.

Без диапазона всего объявления остальные идентификаторы импорта могут обрабатываться как обычные ссылки в контексте `CLASS`.
Это сохраняет возможность ложной подсветки квалификаторов и wildcard imports.

---

## Последствия

Разбор импортов проверяется независимо от Extension Development Host.

`ThrowableHighlightingFinder` использует результаты отдельного компонента вместо построчной проверки.

Автоматические проверки должны покрывать:

- явный импорт типа;
- многострочный импорт;
- комментарии между частями квалифицированного имени;
- явный импорт вложенного типа;
- исключение имён пакетов и внешних типов;
- wildcard imports пакетов и вложенных типов;
- одиночные статические импорты и статические wildcard imports;
- несколько импортов на одной строке;
- сохранение контекста обычных ссылок после завершённого импорта;
- сохранение позиций диапазонов после обработки `JavaCodeMask`;
- исключение import-подобного текста вне Java-кода;
- отсутствие переноса незавершённого импорта в последующие объявления и тела блоков;
- сохранение существующего поведения `CATCH` и `THROWS`.

Состояние реализации и известные ограничения обновляются в документации прототипа после проверки.

---

## Не входит в решение

- Изменение правил определения принадлежности типа к иерархии Throwable;
- Изменение fallback-набора и правил кэширования;
- Исправление обработки text blocks в `JavaCodeMask`;
- Изменение внутренних TypeScript-импортов и конфигурации сборки;
- Полный синтаксический и семантический анализ Java-кода;
- Изменение IntelliJ-плагина;
- Публикация расширения VS Code.
