# ADR-0010: Подсветка типов Throwable в throws в прототипе VS Code

## Статус

Принято.

---

## Контекст

[ADR-0009](0009-throwable-throws-highlighting.md) определяет отдельный контекст `THROWS` для типов `Throwable` и его наследников
в секциях `throws` методов и конструкторов.

Поддерживаемый IntelliJ-плагин реализует это решение. Применение контекста в техническом прототипе VS Code было явно оставлено
за пределами ADR-0009.

Текущий прототип VS Code использует editor decorations и различает контексты `CLASS`, `IMPORT` и `CATCH`. Цвета `IMPORT` и
`CATCH` наследуют `CLASS`, пока пользователь не задаст отдельное значение.

Для сохранения единого контракта Java-подсветки прототип должен различать `Throwable` в секции `throws` независимо от обычных
ссылок на классы и параметров `catch`.

---

## Решение

В прототип VS Code вводится контекст подсветки `THROWS`.

Контекст применяется к ссылке на тип в секции `throws` метода или конструктора, если тип подтверждён как `Throwable` либо
его наследник.

Добавляется настройка `throwableHighlighter.prototype.throwsColor`.

Пустое значение `throwsColor` наследует значение `classColor`. Если оба значения пусты, прототип не создаёт foreground-decoration
и сохраняет стандартный цвет Java-класса.

Подсвечивается только диапазон имени типа. Ключевое слово `throws`, разделители и другие элементы объявления сохраняют
стандартную Java-подсветку.

Каждый тип в списке `throws` определяется и обрабатывается независимо.

Для известных стандартных типов и пользовательских наследников используется существующий механизм определения `Throwable`,
включая `JavaTypeDefinitionResolver`, `ThrowableHierarchyResolver` и правила кэширования.

Контексты `CLASS`, `IMPORT` и `CATCH` сохраняют текущее поведение.

---

## Рассмотренные варианты

### Оставить типы в throws частью контекста CLASS

Вариант отклонён.

Такой подход не соответствует контракту Java-подсветки и не позволяет пользователю настроить контракт метода или конструктора
отдельно от обычных ссылок на классы.

### Использовать общий контекст для catch и throws

Вариант отклонён.

`catch` описывает обработку исключения, а `throws` — контракт метода или конструктора. Контексты имеют разные семантические
роли и должны настраиваться независимо.

### Отложить реализацию до выпуска поддерживаемого расширения VS Code

Вариант отклонён.

Контекст уже определён в общем контракте и реализован в поддерживаемом IntelliJ-плагине. Проверка его применения в техническом
прототипе уменьшает расхождение платформ до принятия решения о публичной поддержке VS Code.

---

## Последствия

Прототип получает настройку отдельного цвета для типов `Throwable` в секциях `throws`.

Необходимо дополнить логику определения контекста в editor decorations, настройки расширения, fixtures, автоматические проверки
и документацию прототипа.

Проверка должна покрывать методы и конструкторы, несколько типов в одном списке `throws`, не-`Throwable` типы, а также сохранение
стандартной подсветки ключевого слова `throws` и разделителей.

Реализация не переводит VS Code из статуса технического прототипа в поддерживаемое пользовательское расширение.

---

## Не входит в решение

- Подсветка ключевого слова `throws`;
- Подсветка Javadoc-тегов `@throws` и `@exception`;
- Изменение поведения контекстов `CLASS`, `IMPORT` и `CATCH`;
- Интерактивная настройка цветов перед публичным выпуском VS Code;
- Публикация расширения в Visual Studio Marketplace;
- Поддержка языков, отличных от Java.
