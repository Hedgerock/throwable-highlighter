# ADR-0035: Разделить процессы выпуска IntelliJ Platform и VS Code

## Статус

Принято.

---

## Контекст

[ADR-0033](0033-vscode-first-public-release.md) определяет независимое версионирование,
сборку и публикацию расширения для VS Code.

GitHub Actions выполняет проверки обеих платформ. Плагин IntelliJ Platform публикуется по тегу `v<major>.<minor>.<patch>`.
Первый выпуск VS Code `0.1.0` опубликован вручную из подготовленного VSIX.

---

## Решение

Источником версии плагина IntelliJ Platform является `build.gradle.kts`. Тег `v<major>.<minor>.<patch>` запускает выпуск
ZIP и публикацию в JetBrains Marketplace.

Источником версии расширения VS Code является `package.json`. Версия пакета в `package-lock.json` синхронизируется с
манифестом. Тег `vscode-v<major>.<minor>.<patch>` запускает отдельный workflow выпуска и публикацию в Visual Studio Marketplace.

Workflow выпуска VS Code проверяет совпадение версии в теге, манифесте и lock-файле. Проверки Node.js, браузерные проверки
и тесты Extension Host выполняются для коммита релизного тега. Обычный CI и релизный workflow используют общие определения этих проверок.

После успешных проверок workflow собирает VSIX через `npm run build` и сохраняет его
как артефакт. Задача публикации загружает этот артефакт и отправляет его в Marketplace.
Ручной запуск выполняет проверки и сохраняет VSIX. Публикация запускается только
при отправке релизного тега.

Задача публикации VS Code использует Trusted Publishing через OIDC и окружение
`vscode-marketplace`. Право `id-token: write` предоставляется задаче публикации.
Окружение принимает теги выпуска VS Code.

Предрелизная проверка производительности выполняется до отправки тега по правилам
[ADR-0031](0031-vscode-release-performance-budgets.md) и
[ADR-0034](0034-vscode-release-java-workspace-state.md). Тег указывает на коммит,
из которого собран проверенный кандидат.

---

## Последствия

Каждая платформа выпускается своим тегом. Версии плагина и расширения обновляются независимо.

VSIX доступен как артефакт workflow для проверки установки. Порядок запуска выпуска и действия при ошибке публикации
описываются в документации по выпуску.

---

## Не входит в решение

- Перенос расширения из каталога `prototypes/vscode`.
- Автоматическое повышение версий и создание релизных тегов.
- Автоматизация контрольных замеров производительности.
