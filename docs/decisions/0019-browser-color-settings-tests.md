# ADR-0019: Браузерные проверки панели настройки цветов VS Code

## Статус

Принято.

---

## Контекст

Панель настройки цветов использует отдельные HTML-шаблоны, CSS и браузерный скрипт.

Автоматические тесты проверяют формирование HTML, сообщения, черновики, применение настроек и жизненный цикл панели.

`ThrowableColorSettingsWebview.test.ts` выполняет настоящий `app.js` с моделью DOM в `node:vm`. Модель не выполняет
браузерную отрисовку и не проверяет фактическое расположение элементов, переполнение, прокрутку и поведение фокуса.

Изменения панели уже требовали исправлений ширины полей, адаптации таблицы и промежуточных состояний элементов управления.

Перед подготовкой публичного выпуска требуется автоматическая проверка взаимодействия и отображения панели в браузере.

---

## Решение

Для браузерных проверок панели используется Playwright Test с Chromium.

Тестовая страница формируется существующим `ThrowableColorSettingsHtml` из настоящих HTML-шаблонов панели. Подключаются
настоящие `styles.css` и `app.js`.

Отдельная копия пользовательской разметки или логики панели для тестов не создаётся.

Тестовое окружение задаёт CSS-переменные и признаки темы, которые панель получает от VS Code.

Обмен с расширением заменяется контролируемой реализацией `acquireVsCodeApi` и сообщений. Ответы и порядок подтверждений
определяются сценарием проверки.

Тестовая реализация обмена размещается отдельно от пользовательских ресурсов панели.
Изменение пользовательского кода только для включения тестового режима не требуется.

### Проверка взаимодействия

Браузерные тесты проверяют:

- текстовый ввод цвета и сохранение фокуса;
- синхронизацию RGB, alpha и предпросмотра;
- доступность полей при разных источниках цвета;
- состояния возврата, удаления, отмены и применения;
- ожидание подтверждений перед выполнением выбранного действия;
- переключение областей `User` и `Workspace`;
- доступ с клавиатуры;
- переполнение таблицы и горизонтальную прокрутку.

Проверки учитывают промежуточные состояния элементов управления, включая доступность кнопок и выбор области до получения
подтверждений.

Ожидание строится по наблюдаемому состоянию страницы и управляемым сообщениям. Произвольные задержки не используются как
условие готовности интерфейса.

### Проверка отображения

Отображение проверяется сравнением с эталонными скриншотами.

Начальный набор содержит четыре варианта одного фиксированного состояния панели:

- широкая панель в тёмной теме;
- широкая панель в светлой теме;
- узкая панель в тёмной теме;
- узкая панель в светлой теме.

Размеры окна, масштаб, шрифты и данные сценария фиксируются в тестовом окружении.

Эталоны формируются и сравниваются в одном версионированном окружении Linux. Версии Playwright и используемого браузера
согласуются с этим окружением.

Обновление эталонов выполняется явно после проверки ожидаемого изменения интерфейса. Обычный прогон CI не перезаписывает
эталоны.

### Запуск проверок

Браузерные проверки запускаются отдельной локальной командой и отдельной job GitHub Actions.

Ошибка браузерного сценария или сравнения скриншота завершает проверку с ненулевым кодом.

При ошибке CI сохраняет отчёт и диагностические материалы, включая полученное изображение и различия с эталоном.

Существующие компонентные проверки сохраняются. Текущий состав локального `pre-commit` не изменяется.

Решение дополняет автоматические проверки прототипа. Правила выбора локальных проверок из ADR-0018 сохраняют силу.

---

## Рассмотренные варианты

### Сохранить только существующие компонентные тесты

Вариант отклонён.

Модель DOM не обнаруживает ошибки браузерной отрисовки, переполнения и фактического взаимодействия с элементами.

### Сразу автоматизировать весь интерфейс VS Code

Вариант отложен.

Проверка всей среды включает запуск редактора, установку расширений и готовность Java-поддержки. Для проверки представления
панели достаточно отдельного браузерного окружения.

Проверка с настоящим VS Code остаётся отдельным этапом.

---

## Последствия

Прототип получает зависимость разработки Playwright и отдельную инфраструктуру браузерных проверок.

Эталонные изображения хранятся в репозитории. Отчёты, traces и результаты неуспешных запусков в репозиторий не добавляются.

Изменения разметки и оформления требуют проверки браузерных сценариев и ожидаемых различий изображений.

Браузерные тесты подтверждают поведение представления при заданном обмене сообщениями. Работа VS Code API, сохранение
настоящей конфигурации и применение Java decorations проверяются отдельно.

Порядок запуска, обновления эталонов и разбора ошибок описывается в документации прототипа после реализации.

---

## Не входит в решение

- Автоматизация всего интерфейса VS Code;
- Проверка настоящего Definition Provider и готовности Java-поддержки;
- Проверка установки VSIX и публикации расширения;
- Автоматизация системного диалога выбора цвета;
- Проверка всех пользовательских тем;
- Изменение поведения панели и модели цветов;
- Изменение IntelliJ-плагина;
- Принятие публичной поддержки VS Code.
